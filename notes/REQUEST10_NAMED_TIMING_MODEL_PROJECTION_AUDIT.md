# Request 10.6: Named Timing-Model Projection Audit

## Goal

Status: Counterexample candidate. Decide whether the named `J0337` / `Nutimo`
timing implementation is closer to the finite shared phase/geometric
projection manifold from Request 10.5 or to arbitrary per-carrier complex
projection nuisance.

This is a source-inspection gate only. No `Nutimo`, `Tempo2`, `PEP`, TOA fit,
dependency provisioning, or runtime build was attempted.

## Imported Gate

Status: Imported from prior work. Request 10.5 classified the three-carrier
dynamic-chi bridge:

- finite shared phase/geometric projection: `conditional`,
  `runtime-motivated`,
- independent per-carrier complex projection: `collapse`,
  `not-runtime-motivated`.

Status: Imported from prior work. The carrier set is

```text
Omega_in, Omega_out, |Omega_in - Omega_out|.
```

Status: Imported from prior work. The dynamic target is the shared finite

```text
G(z) = c_Y + beta/(1 + tau_chi z).
```

## Named-Model Evidence

Status: Proven. `Parameters.h:63-122` defines a finite fitted parameter map:
spin, inner-orbit, outer-orbit, mass, orientation, SEP, sky, dispersion, and
extra-body parameters. The standard parameter map is not expressed as one
independent complex amplitude per carrier.

Status: Proven. `Parameters.cpp:2216-2278` marks orbital, SEP, and extra-body
parameter changes as `motion_changed`; later conversion paths route through
`Compute_state_vectors`. This means carrier structure is generated by changing
finite physical parameters and recomputing shared state vectors.

Status: Proven. `Fittriple-compute.cpp:167-260` calls the delay routines with
the shared state vectors `sp`, `si`, `so` and line-of-sight / observer geometry.
`Delay_brut.cpp:512-735` documents the non-geometric and geometric delay
interfaces using the same state-vector inputs.

Status: Proven. `Delay_brut.cpp:715-809` computes the geometric/Roemer
projection from the pulsar state and line-of-sight vector, with finite
Kopeikin/Shklovskii corrections and delay-component output. This is a
finite geometry projection, not per-carrier complex freedom.

Status: Proven. `Compute_gradients.cpp:54-199` constructs residual gradients
with respect to the finite fitted parameter list. This provides a named-code
route to a finite Jacobian audit if an external runtime environment is later
used.

## Collapse Risk

Status: Proven. `Fittriple-compute.cpp:343-383` contains an `RN_PL` special
case with explicit sinusoid amplitudes and phases such as `ds_A1`, `ds_phi1`,
`ds_A2`, and `ds_phi2`. If enabled on the target carrier set, this behaves like
the arbitrary harmonic nuisance class and can absorb carrier-level amplitude
and phase relations.

Status: Proven. Therefore a dynamic-chi runtime hand-off must disable this
special case or treat it as a separate nuisance-soak-up comparator. It cannot
be included silently in the same observable claim.

## Verdict

Status: Counterexample candidate. The standard `Nutimo` triple timing core
appears to be a finite shared state/geometry manifold rather than arbitrary
per-carrier complex projection. This places the named implementation on the
`conditional`, `runtime-motivated` side of the Request 10.5 gate.

Status: Proven. The same source tree also contains at least one explicit
harmonic special case that would collapse the bridge if admitted on the target
carriers.

Status: Counterexample candidate. The precise runtime-worthy statement is:

```text
dynamic-chi is runtime-motivated for a standard integrated three-body Nutimo
configuration that preserves finite state/geometry projection and excludes
arbitrary per-harmonic carrier nuisance on the target frequencies.
```

Status: Conjectural. A real runtime hand-off would still need to verify the
actual fit configuration, active special cases, and dynamic-chi column rank
against the named finite-parameter Jacobian.
