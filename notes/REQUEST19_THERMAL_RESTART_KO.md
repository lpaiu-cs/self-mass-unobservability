## 실행과 근거 위치

실행 전 체크포인트는 `15b77ea`, 재현 검증 후 질량 보정 전 체크포인트는 `4c630db`다. 실행 캐시는 WSL Ubuntu-22.04의 `/home/lpaiu/work/thermal-restart19`에 두었다. 공개 원본을 복원한 단계와 물리적으로 변경한 단계를 다른 디렉터리로 나눴고, 실패 로그도 남겼다.

재실행 진입점은 `verification/thermal_restart.py`다. 저장된 증거만 독립 검사하려면 저장소 루트에서 다음을 실행한다.

```powershell
rtk proxy wsl -d Ubuntu-22.04 -- bash -lc 'cd /mnt/e/lab/self-mass-unobservability && PYTHONPATH=/home/lpaiu/work/nutimo_pilot/request13_deps python3 verification/thermal_restart.py check'
rtk proxy wsl -d Ubuntu-22.04 -- bash -lc 'cd /mnt/e/lab/self-mass-unobservability && python3 verification/thermal_restart.py verify'
```

새 실행 캐시의 준비 순서는 `sdk_download`, `mesa_download`, `restore_inputs`다. SDK tar.gz와 MESA ZIP을 해당 캐시에 풀고, 배포본의 chem·colors·eos·kap·ionization·atm `build_data_and_export`를 각각의 패키지 디렉터리에서 실행한다. 소스 전체를 재컴파일하지 않고 검증된 원래 실행 파일을 사용한다. `environment`가 전체 배포 MD5, 소스 조각, 데이터와 공유 라이브러리 해시를 묶는다.

양성 대조는 `prepare 19000 19001 <새이름>` → `calcium_network <새이름>` → `resume_controls <새이름>` → `run <새이름>` → `compare <새이름>` 순서다. 전체 재현은 `prepare 18000 19000 replay18000` 후 같은 네트워크·제어 복원, `target_profile replay18000`, `run replay18000 4`, `trajectory`, `target_response` 순서다. 질량 대조는 `prepare 18000 19500 mass18000` 후 같은 복원, `mass_trial mass18000`, `run mass18000 4`, `mass_selection`, `mass_response` 순서다. `run`은 이미 실행 로그가 있는 디렉터리를 덮어쓰지 않는다. 실패 대조는 원래 설정 그대로의 `restore19000`과 핵종만 복원한 `calcium19000`이다.

주요 산출물은 `outputs/thermal-restart19`에 있다. `runs/`에는 실제 설정과 압축 이력, `published-history-window.data.gz`에는 원래 이력의 비교 구간, `target-model18969.data.gz`와 `mass-trial-best.data.gz`에는 선택한 실제 구조가 있다. `audit.json`은 구조·이력·독립 균일 구·산술 구간 검증을, `gates.json`은 완료와 미완료 경계를 기록한다. 기존 Request 13–18 근거와 원고 PDF·ZIP은 보존하고 다섯 유지 문서의 이전 버전은 해시에 결속된 스냅샷으로 남겼다.
