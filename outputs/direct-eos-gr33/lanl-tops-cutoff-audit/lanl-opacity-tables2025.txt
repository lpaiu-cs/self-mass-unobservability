This document describes details of the structure and content of the SESAME database. This
includes details on both legacy table structures and new tables structures, which improve represen-
tations of phase speciﬁc thermodynamic properties and explicitly provide tabulated phase bound-
aries. Such database augmentations will provide improved physical representations of equilibrium
mixed phase regions. In addition to accurate modeling of mixed phases, the new phase speciﬁc
tables provide a framework for the implementation of important non-equilibrium kinetic modeling
of phase transitions.

I. INTRODUCTION
Modeling of the thermodynamic equation of state (EOS) of various materials has had a long storied tradition at
LANL. As early as 1949 Feynman, Metropolis, and Teller published a paper presenting EOS values for some elements
and a methodology for calculating the EOS at high compression [1]. Cowan and Ashkin made notable methodology
improvements for compressed materials throughout the 1950’s and beyond [2]. In 1971 Jack Barnes and Jerry Rood
created the SESAME database and by 1972 the database became publicly available. This database was designed
around materials identiﬁed by a material ID number. The thermodynamic state variables are then tabulated on a
density (ρ) and temperature (T ) grid. The original modeling centered around segregating the EOS into a three part
decomposition of the Helmholtz free energy [3],
A(ρ,T ) =Ac(ρ) +Aion(ρ,T ) +Aele(ρ,T ) (1)
whereAc(ρ) =A(ρ,T =0), known as the cold curve, models the compression response of the material as a function of
density. Aion captures the energy contributions due to ionic/atomic vibrations, rotations, and translations. Finally
Aele models the response to electronic excitations. This decomposition is evident in the structure and design of
SESAME and can clearly be seen in Table II, presented later, where the total EOS corresponds to the 301 table.
Additionally, the cold curve, ion EOS and electronic EOS are tabulated in the 306, 305, and 304 tables respectively.
The SESAME database is celebrating its 53 rd anniversary of its public release this year, and as with any database
this old, over the years it has become necessary to rework the details. This includes expanding the deﬁnition of
table types and the scope of data represented to reﬂect advances in materials physics and code advancements, which
make modeling physics details possible. The last document that comprehensively detailed the SESAME structure
was locally published in 1992 [4]. This report will regurgitate some information from that report, modifying where
required, adding long existing tables that were not included, and deﬁning brand new tables which will facilitate
the future of explicit phase-aware material properties. This extension to a multi-phase material description requires
tabulating phases individually, tabulation of phase boundaries, triple point tables, and naturally leads to extension of
phase speciﬁc shear. Phase speciﬁc “grey” (or “gray”) opacity and conductivity tables will not be expanded at this
point but it would be straight forward to use the generalized frame work to do so in the future when required.
The inclusion and formal deﬁnition of phase-speciﬁc tables in SESAME is long overdue. As host-codes required
access to individual phases in addition to a ﬂattened total EOS, EOS developers quickly adapted by creating multiple
materials, one ﬂattened EOS with a formal SESAME material ID number and a separate material with a “unique”
material ID number for each phase. Though eﬀective and quick, this has lead to an explosion of SESAME materials
with no formal mapping between a given ﬂattened EOS material and individual phases that were used to create it.
By including everything under the deﬁnition of one material going forward, we ensure a self-consistent pedigree for
the entire material.
This report will include a section on physics notation and nomenclature (Section II), discussion of existing and
new tables and their structure (Section III), data requirements and expectations for the new phase-boundary tables
(Section IV K), a short section and reference to the newly released ASCII2 SESAME ﬁle format (Section V), and an
overview of existing software made to directly interact with SESAME data.

A. Structure of SESAME Data
The data for each table in SESAME is stored as a 1-D array (single stream of numbers). Typically, the ﬁrst couple
of values in the array determine the extents of the arrays for the independent variables. The two-dimensional tables
in SESAME are tabulated as functions of density and temperature, f(ρ,T ). There are also one-dimensional tables
tabulated as functions of density, f(ρ). Tables IV to VIII list the data structures of each SESAME construct, the
column Index, also often referred to as WORD, is a relative index oﬀset where each new array begins. It should be
noted that this is only in reference to the order of the data and includes neither an ascii-ﬁle-format-speciﬁc header
nor a binary-ﬁle-format-speciﬁc index that identiﬁes which SESAME table is being tabulated. These format speciﬁc
headers are described in Section V.

IV. GENERAL T ABLE DISCUSSIONS
This section provides some general descriptions and/or discussions about various groups of tables, and the data
they contain, as deﬁned for and exists within the SESAME database.
A. 101-style Comment T ables
The 101 comment table is designed to contain speciﬁc metadata for a SESAME material, and the possible table
number values (i.e., a Table_ID) are 101 and the range 10101-10199. Tables 10101-10199 are intended to carry the
same speciﬁc metadata relevant to each phase. The phase speciﬁc metadata for phase 1 is contained in table 10101,
for phase 2 in 10102, etcetera. Keywords in the 101-style table are described in the following bulleted list (bold;
including period, ’.’). Note that Table_ID 101 and 10101-10199 are speciﬁcally reserved for 101 style data. Although
it has not strictly enforced throughout the history of LANL’s[12] SESAME parsers, certain conventions are assumed
by LANL EOS software and should be followed. The case of a keyword is not enforced (i.e., case-insensitive).
• material. Material or phase name (z=atomic number, a=atomic weight)
• source. Author, organization detail.
• date. Date the material was created.
PAGE 16
13
• refs. Published references.
• comp. Composition of the material.
• code. Named software used to create the material data.
• classiﬁcation. Unclassiﬁed, CUI::SP-EXPT (formally Export Controlled), Secret Restricted Data or other
LANL approved classiﬁcation marking[13].
• phases. An optional string containing a comma-delimited list of the number of phases followed by an ordered
phase names. Some conventions are generally assumed for the string content:
– It is assumed that any leading and/or trailing white space will be ignored for each phase name.
– The left-to-right order of these phase names must correspond to the data order in any other table that
contains phase-speciﬁc data (e.g., 321, 10101, 10102, 10103, 30101, 30102, 30103, etc.).
– The ﬁrst phase listed corresponds to the ambient phase data.
– The last phase listed is the high-temperature phase, which usually corresponds to the liquid phase data.

B. Generic comment table
Generic comment tables are potentially-numbered with a Table_ID in the range of 102-199, and they have neither
any explicit keywords deﬁnitions nor any required organizational structure. These comments are intended to provide
the consumer of SESAME data with useful information about the data pedigree and history.
C. Material constants: 201
Several scalar material constants are stored in the 201 table (table IV). The mean atomic number, mean atomic mass,
and normal density are consistently tabulated, and they correspond to the values supplied via the OPENSESAME[6]
input; however, a large majority of the adiabatic bulk modulus and exchange coeﬃcient data are assigned useless zero
values within the aggregated SESAME database.

D. 300 series tables
The 300 series tables represent SESAME’s fundamental EOS data. As alluded in section III A and implied in
table IV, the 300 series tables contain ﬁve main arrays. There exist two one-dimensional independent variable arrays
containing density and temperature data, and there are three two-dimensional, column-major [14] arrays containing
density- and temperature-dependent thermodynamic functions: pressure, internal energy, and Helmholtz free energy.
The 306 style table also follows this structure, but the temperature array only contains one value, T = 0K. What
the table IV fails to convey is the implied physical and numerical requirements of the data stored in 300 series tables.
The following is an attempt to explicitly list the implicit requirements of these data.
• The density array shall be monotonically increasing with a minimum possible value of zero.
• The temperature array shall be monotonically increasing with a minimum possible value of zero.
• Best practice is for the temperature array to start with zero.
• Internal-energy shall monotonically increase as a function of temperature at a given density.
• Helmholtz free-energy shall monotonically decrease as a function of temperature at a given density.
• Helmoholtz free-energy and internal-energy shall be identical at T = 0.
• The dependent data (i.e., pressure, internal energy, and Helmholtz free energy) in the 301 should equal the sum
of the data in each of the 304, 305, and 306 tables.
• Density and temperature arrays should be approximately evenly log-spaced, with extra resolution where the
absolute values of the ﬁrst and/or second derivatives are large.
• Other thermodynamic consistency checks, based on Maxwell equations, shall be enforced.
E. Mass fraction table: 321
The 321 table is a variation of a 300-series table that contains equilibrium mass fraction data for each material
phase corresponding to the tabulated density and temperature grid of an EOS. The data associated with the liquid
(i.e., ﬂuid) phase of the EOS is tabulated last; In other words, the liquid phase index will be the largest of all
tabulated phases within a 321 table (e.g., phase 1: bcc, phase 2: hcp, phase 3: liquid). The 321 table is similar to a
301 table in that there are multiple two-dimensional, density- and temperature-dependent arrays stored in sequence;
however, the number of these arrays is not limited to a maximum of three as is the case for the 301 table. Instead, the
number of material phases that are represented is what determines the total array count. Table IV contains a visual
representation of how data is organized in a 321 table, directly contrasted to how data in a 301 table is organized. As
described in the previous section (section IV D), the following is an attempt to explicitly list the implicit requirements
of these mass fraction data.
• The density array shall be monotonically increasing with a minimum possible value of zero, and correspond to
the related 300-series tables.
• The temperature array shall be monotonically increasing with a minimum possible value of zero, and correspond
to the related 300-series tables.
• Best practice is for the temperature array to start with zero.
• The dependent data (i.e., equilibrium mass fraction data) in all of the individual phase-speciﬁc arrays should
sum to a value of 1 at each (density,temperature) grid location.
• Density and temperature arrays should be approximately evenly log-spaced as is done for the 300-series tables
described in section IV D.

F. V apor-dome table: 401
The 401 table is designed to contain a one-dimensional grid representation of the EOS’ vapor dome phase bound-
ary. This boundary is represented by tabulated data for the following thermodynamic quantities: Temperature
(K), Vapor Pressure (GPa), Vapor Density on coexistence line ( Mg/m 3), Liquid-or-Solid Density on coexistence
line (Mg/m 3), Vapor Speciﬁc-Internal-Energy ( MJ/kg ), Liquid-or-Solid Speciﬁc-Internal-Energy ( MJ/kg ), Vapor
Speciﬁc-Helmholtz-Free-Energy (MJ/kg ), and Liquid-or-Solid Speciﬁc-Helmholtz-Free-Energy (MJ/kg ). The Vapor-
speciﬁc data represent the vapor dome phase boundary for densities less than or equal to the EOS’ critical point.
Alternatively, the Liquid-or-Solid-speciﬁc data represent the vapor dome phase boundary for densities greater than
or equal to the EOS’ critical point. Both the pressure and temperature arrays are common to the other Vapor-
and Liquid-or-Solid-speciﬁc arrays stored within the 401 table. In other words, either the temperature or pressure
arrays can be used as a common grid for the other tabulated thermodynamic quantities. Table V contains a visual
representation of how data is organized in a 401 table.
G. Melt tables: 411 and 412
The 411 and 412 tables contain a tabulated representation of the EOS solid-to-liquid melt transition region. This
phase change region is bounded by both a solid (411) and a liquid (412) tabulated boundaries that are density-
dependent arrays of the following thermodynamic data: Melt Temperature ( K), Melt Pressure (GPa ), Melt Speciﬁc-
Internal-Energy (MJ/kg ), and Melt Speciﬁc-Helmholtz-Free-Energy (MJ/kg ). Table V contains a visual representa-
tion of how data is organized in both a 411 and a 412 tables. The density grid in these tables should be monotonically
increasing. Ideally 411 and 412 tables should be consistent with the 301 table for a given material ID. For example,
starting with a tabulated density from the 411 table and retrieving the corresponding temperature and pressure tab-
ulated at that density point, one should be able to interpolate a consistent pressure from the 301 table at the same
density and temperature. In practice, this is only true for 301 tables constructed where an explicit melt transition was
modeled in the 301 table, 411 and 412 tables generated alongside the multiphase-ﬂatting algorithm were introduced to
the database around 2010. For legacy materials and materials using legacy modeling techniques most of melt tables
were generated so that the 411 table is consistent with the 301 and the 412 table is shifted for a ﬁxed change in
entropy, typically not consistent with the 301 table.
H. Shear: the expansion of the 431 table and the demise of the 432 table
The 431 table contains cold shear modulus ( GPa ) and optionally a second array containing the shear modulus at
the melting temperature as a function of density. Cold shear modulus in this context is the shear modulus at T = 0k.
When using the shear modulus at melt array, the melting temperature at a given density is not tabulated explicitly
so one should use these in conjunction with the melt tables described in Section IV G. Table VI contains a visual
representation of how data is organized. This new extension of the 431 to optionally include shear modulus at melt is
an adaptation intended to include data that was previously stored in the undocumented 432 table. The now obsolete
432 table structure is deﬁned exactly like the expanded 431 table where the second array containing shear at melt
data is not optional. In current SESAME releases these tables have been combined into a single 431 table. This
document also deﬁnes phase-speciﬁc 431-style tables 43101-43199 as place holders for future materials that might
take advantage of phase dependent shear modulus.

I. Gray opacity tables: 500 series
The 500 series tables contain the SESAME opacity data, which are so-called “gray” (or “grey”) Rosseland and
Planck mean opacities, and they are provided for a prescribed grid of temperatures and densities. The Rosseland and
Planck mean data are contained within the 502 and 505 SESAME tables respectively. (For completeness, we mention
that the 504 table contains the mean ion charge (i.e., free electrons per atom) that is consistent with the opacity
calculations. Also, the 503 table contains the electron conductive opacity, when available[15]. These SESAME opacity
data are obtained by processing the Los Alamos OPLIB opacity database[16], which contains detailed, frequency-
dependent opacities for pure elements. The fundamental atomic data that are needed to calculate the OPLIB opacities
are generated with the Los Alamos suite of atomic physics codes[17]. The SESAME gray opacity data are obtained by
integrating the frequency-dependent OPLIB data, convolved with the appropriate (Rosseland or Planck) weighting
function. This processing of the OPLIB opacities is done with the TOPS codes[18, 19], which can also be used in a
more general context to produce opacity ﬁles, for both pure elements and mixtures, that can be used in radiation-
hydrodynamics codes.
As seen in table VI, the 500 series tables store logarithmically-transformed (base 10) data.
J. Conductivity tables: 600 series
The 600 series tables contain electrical conductivity (602), thermal conductivity (603), the thermoelectric coeﬃcient
(604) and the electron conductive opacity (605). These are tabulated in Gaussian units. Table 601 reports the mean
ion charge, which, in older Ziman-like conductivity models, is a key parameter. For modern tables this quantity is
often not as directly related to the transport quantities. Recent 600 tables have been produced by direct calculation,
using density functional theory and kinetic theory [20, 21]. Older tables used the Ziman model and should be used
with caution [20, 22].
As speciﬁed in table VI, the 600 series tables contain logarithmically-transformed (base 10) data.
K. Phase-boundary tables, 421yyxx and 422yyxx series
The equilibrium phase boundary between two phases can be found using either the Helmholtz free-energy and a
lever rule or by equating the Gibbs free-energy of two phases i and j.
Gi(Pi,T i) =Gj(Pj,T j) (2)
where Pi =Pj =P
and Ti =Tj =T
Gi(P,T ) =Gj(P,T ) (3)
From eq. (2) one should be able to search Gibbs free energy for a pressure, P , along isotherms to ﬁnd the relevant
phase boundary. When using SESAME data to create these boundaries one can experience diﬃculties when attempting
to solve the Gibbs intersection for the solid/liquid to vapor transition, due to the Van-der-Waals loops in the underlying
expansion models used to create 301 tables in the expansion region of the EOS. For this reason, users are encouraged
to employ the legacy “vapor dome” data, which is tabulated in the 401 table. A signiﬁcant caveat is that when working
with tabulated data, one needs to keep in mind that formally equivalent thermodynamic expressions will give diﬀerent
results based on the grid spacing and the selected interpolator. These phase boundaries have been computed using
a bi-rational interpolator implemented in EOSPAC6 to maintain consistency with LANL’s use of total EOS tables
(301). The 421yyxx tables are tabulated with respect to increasing density, and they deﬁne a lower-bound or minimum

17
temperature boundary for the associated single phase. The 422yyxx tables are also ordered with respect to increasing
density, and they represent the upper-bound or maximum temperature for the associated single phase. Together the
421yyxx and 422yyxx tables enclose a single phase region. A best practice includes explicitly tabulating grid points
that intersect with tabulated triple-point tables in order to minimize interpolator variance between diﬀerent SESAME
tables.
L. T riple point tables: 423zz series
A triple-point occurs when the Gibbs free energy for three phases are equal at the same temperature and pressure.
Gi(Pi,T i) =Gj(Pj,T j) =Gk(Pk,T k) (4)
where Pi =Pj =Pk =P
and Ti =Tj =T =k=T
Gi(P,T ) =Gj(P,T ) =Gk(P,T ) (5)
Using this data for interpolation can be tricky, since for a ( P ,T ) domain, the Gibb’s free energy is represented as a
single point in phase space. Alternatively, for a ( ρ,T ) independent domain, the Gibb’s free energy is represented by
a line. Only in a ( ρ,U) domain can all thermodynamic variables be resolved when provided only two independent
variables.
V. SESAME FILE FORMA TS
The SESAME data library contains both thermodynamic (e.g., equation of state) and transport coeﬃcients (e.g.,
opacity and conductivity). Note, for simplicity, the term EOS (equation of state) used herein includes both thermo-
dynamic variables and transport coeﬃcients. With the addition of the new phase speciﬁc tables, boundary tables
and triple-point tables to the formal deﬁnition of SESAME, we were forced to stop using the legacy ﬁxed-format
ASCII format[23]. A new ASCII2 format has been deﬁned [24], which closely resembles the legacy ASCII format
while relaxing some of the overly-restrictive FORTRAN ﬁxed-format write statements, enabling expanded material
identiﬁcation numbers, implementing expanded table identiﬁcation numbering, and outlining a more parser friendly
whitespace delimited format for the numerical data tables. Reworking the entire format for human readability was
considered, but we opted to retain the various data structures so that the ASCII2 format commutes with tables
stored the SESAME binary format [4]. Keeping data structures consistent should also minimize the work required
for external codes that rely on the ASCII format to update their SESAME parsers to handle ASCII2 ﬁles.
Some limited support for conversion between the new ASCII2 format and some of LANL’s legacy formats is
provided by a utility called convert_sesame_data, which is included within the EOSPAC6[5] version 6.5.11 and
newer distributions. Previous versions of EOSPAC6 provided limited – albeit incomplete – support as this new
ASCII2 format evolved into the current description. New materials contain tables that are incompatible with older
SESAME formats, namely the original ASCII format[23] and the Helios format,[25]. For the foreseeable future, LANL
will only be distributing ASCII2 formatted SESAME data outside of the USDOE[26] complex and both ASCII2
and binary formats internally. Updating codes to be consistent with the new format will be required for modern
SESAME materials. We strongly recommend interacting with the data using either EOSPAC6[5] or its oﬃcially-
supported successor. EOSPAC6 not only provides interpolation and inversion[27] of data, it also provides access to
and interpolation of thermodynamically-derived data that is not explicitly tabulated in SESAME.
